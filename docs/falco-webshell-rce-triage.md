# 런타임 위협 트리아지 — 웹셸/RCE 클래스 (Falco 연동)

> 대상 시나리오: `fixtures/scenarios/fx-scn-01-webshell-rce-falco.json`
> 통제 원칙은 그대로다 — **Watchman 은 조사·제안만 하고, 격리·차단을 스스로 실행하지 않는다.**

## 1. 왜 이 클래스를 다루나 (실제 사고 근거)

2025년 8월 **롯데카드 침해사고**는 이 프로젝트가 방어 대상으로 삼는 유형과 정확히 겹친다.
금융위원회 공식 발표에 따르면, 미상의 해커가 롯데카드의 **온라인 결제서버(WAS)** 에 침입해
악성 프로그램인 **웹셸(Web Shell)** 을 설치하고 8.14~8.27 기간 중 **총 200GB** 의 정보를
유출했다(신고 시점 1.7GB → 조사 결과 200GB). 유출 정보에는 **296.9만명** 의 개인신용정보가
포함됐고, 그중 약 28.3만명(9.5%)은 카드 비밀번호·CVC 까지 노출됐다.[^fsc]

금융감독원·금융보안원 합동조사는 침투 경로를 **오라클 웹로직(Oracle WebLogic) 서버의
원격코드실행 취약점 `CVE-2017-10271`** 로 분석했다. 이 취약점은 **인증 없이** 특수 조작된
XML(WLS Security 서브컴포넌트, T3/HTTP)로 원격 명령을 실행해 서버를 완전히 장악할 수 있는
결함으로, **2017년 10월 패치가 이미 제공**됐다.[^nvd][^oracle] 롯데카드는 전자금융기반시설
운영 서버인 **48개 웹로직 중 1대를 자산목록에서 누락**해 7년간 미패치로 방치했고, 공격자는
침투 후 웹셸(3개 서버에서 웹셸 5종·악성코드 2종 확인)을 심어 내부망 장악과 자료 반출을
시도했다.[^isac][^assembly] 전문가들은 **APT(지능형 지속 위협)** 수법으로 보고, 재발방지책으로
**신속한 패치·외부 노출 서버 정기 점검·WAF·위협 탐지 시스템 강화**를 지목했다.[^news1]

핵심은 **패치가 뚫린 게 아니라 "패치가 있는데도 자산이 안 보였다"** 는 점이다. 초기 침투를
막지 못하는 상황을 전제로, **런타임에서 웹셸 실행 흔적을 조기에 잡아 사람에게 근거와 함께
올리는 것** 이 Watchman 이 이 클래스에 기여하는 지점이다.

## 2. 탐지 신호 (Falco 런타임 룰 → Alertmanager → Watchman)

웹셸은 정상 결제 트래픽의 정상 포트(80/443)를 타고 들어와, 서버사이드 스크립트(JSP 등)로
심긴 뒤 **웹서버(WAS) 프로세스가 셸/명령을 실행**하는 순간 런타임에 흔적을 남긴다. 이 흔적은
Falco 의 커널 시스템콜 관측으로 잡히며, 대표 룰은 다음과 같다(모두 Falco 기본 룰셋 또는
그 변형):

| Falco 룰 | 잡는 것 | 웹셸/RCE 매핑 |
|---|---|---|
| **Terminal shell in container** | 컨테이너에서 예기치 않은 대화형 셸 spawn | 웹셸이 `/bin/sh` 를 띄워 명령 실행 |
| **Run shell untrusted / Web server spawned shell** | 웹서버 프로세스(java·nginx·httpd)가 셸 자식 생성 | WAS(java)→sh 프로세스 계보 = 웹셸의 결정적 징후 |
| **Write below binary/web dir** | 웹 도큐먼트 루트·바이너리 경로 하위 파일 쓰기 | `.jsp` 웹셸 신규 업로드 |
| **Unexpected outbound connection** | 파드가 허용목록 밖 목적지로 신규 아웃바운드 | 자료 반출·C2 세션(정상 포트 위장) |
| **Read sensitive file untrusted** | 시스템 계정·설정 파일 조회 | 정찰(reconnaissance) 단계 |

경로: **Falco → falcosidekick → Alertmanager → Watchman webhook.** Watchman 입장에서는
그냥 또 하나의 Alertmanager 알림이므로 **새 수집 도구가 필요 없다.** 픽스처
`fx-scn-01-webshell-rce-falco.json` 은 이 경로로 도착하는 `FalcoTerminalShellInContainer`
알림(라벨 `source=falco`, `priority=Critical`, 결제 WAS 파드)을 그대로 재현한 것이다.

## 3. Watchman 의 트리아지 (관측→판단→제안, 실행 없음)

1. **관측(read-only)** — 기존 두 도구만 쓴다.
   - `es_search`: 해당 파드의 로그에서 셸 실행·`.jsp` 접근·비정상 아웃바운드 흔적 상관.
   - `kube_read`(GET/LIST): 파드 스펙·이벤트·소속 워크로드·네트워크 정책 현황 조회.
2. **판단** — "오탐 아닌가"를 강제 검토(배포 스크립트·정상 운영 셸과 구분), 웹셸/RCE 여부와
   확신도를 분류.
3. **제안(실행 아님)** — 카드에 담는 **봉쇄 제안**은 사람이 승인·집행한다:
   - 해당 파드 **네트워크 격리**(NetworkPolicy deny 또는 워크로드 cordon) — *제안*.
   - **포렌식 보존**(파드 스냅샷/로그 확보) 후 재기동 판단 — *제안*.
   - 노출 자산 **패치·자산목록 재점검**(웹로직 CPU 적용), 외부 노출면 축소 — *제안*.
   - 영향 계정·키 **회전** 검토 — *제안*.

이 시나리오에서도 6축 통제는 그대로 유효하다: 제안 카드는 **텍스트일 뿐**이고(④ 실행 도구
없음), 알림 본문에 섞인 지시는 주입 감지층이 잡으며(①), 에이전트는 여전히 읽기 전용·비루트·
이그레스 허용목록 안에서만 돈다(②③⑥). 즉 **"방어 대상(웹셸/RCE)"을 다루면서도
에이전트 자신이 새로운 공격면이 되지 않는다.**

## 4. 실측 (P4 정직 원칙 — 측정한 것만)

`fixtures/scenarios/fx-scn-01-webshell-rce-falco.json` 을 **결정론적 mock 파이프라인**으로
1회 통과시킨 결과(`LLM_MODE=mock`, 감사로그 격리):

- 주입 감지(프로덕션과 동일 표면, 봉투 전체 JSON 스캔): **0건** — 오탐 없음.
- 루프: **완주(state=완료, partial=None)**, finish 스키마 **유효**, evidence **1건**.

> 이 수치는 **분류 정확도가 아니다.** mock 은 제어 흐름·출력 계약·주입 오탐 없음만 재현
> 검증한다(다른 케이스 뱅크와 동일 기준: 완주+스키마+evidence+주입오탐없음). 실 NIM 분류
> 정확도는 in-cluster 파드가 실관측한 run 을 `eval/score_cases.py` 로 채점한 값이 근거다.

## 5. 범위와 남은 일 (정직)

- **된 것**: 알림 픽스처 + 룰 매핑 + 트리아지/제안 설계 + mock 파이프라인 완주 실측.
- **아직 안 된 것(STRETCH)**: 클러스터에 **Falco + falcosidekick 실배포**, falcosidekick→
  Alertmanager 라우팅 실배선, 실 웹셸 재현 환경에서의 라이브 트리아지·라벨링. 이건
  프로토타입 제출 범위 밖이며 ROADMAP STRETCH 로 둔다 — **설계·픽스처는 갖췄고, 라이브
  배선은 미완**임을 그대로 표기한다.
