# 세션 하이재킹 트리아지 — JWT/세션 토큰 리플레이 클래스 (인증·세션 감사 연동)

> 대상 시나리오: `fixtures/scenarios/fx-scn-05-jwt-session-replay-hijack.json`
> 통제 원칙은 그대로다 — **Watchman 은 조사·제안만 하고, 회전·폐기·격리를 스스로 실행하지 않는다.**

## 1. 왜 이 클래스를 다루나 (실제 사고 근거)

앞선 시나리오들과 종류가 또 다르다. 웹셸(fx-scn-01)은 런타임 RCE, GitHub 마스터키
(fx-scn-02)는 정적 자격증명 탈취, 상담 API(fx-scn-03)는 인가 결함(BOLA)이었다. 이 클래스는
**유효한 "세션" 자체가 탈취돼 정상 사용자로 위장되는** 세션 하이재킹/토큰 리플레이다. 탈취된
것은 비밀번호가 아니라 **이미 인증을 통과한 세션 쿠키/JWT** 이므로, 서버 입장에서 그 토큰은
서명이 유효하고 만료 전이며 2FA 도 이미 통과한 상태다.

두 건의 1차 사고가 이 유형을 정확히 보여준다. **CircleCI(2023-01 공식 리포트)** — 한 엔지니어
노트북에 심긴 악성코드가 **유효한 2FA-backed SSO 세션을 탈취**했다. 노트북은 2022-12-16 감염됐고
백신은 이를 탐지하지 못했으며, 악성코드가 **세션 쿠키 탈취를 실행해 원격지에서 그 직원을
위장(impersonate ... in a remote location)** 하고 프로덕션 시스템으로 권한을 확대했다. 정찰은
12/19, 데이터 유출은 12/22, 회사가 해당 계정 접근을 차단한 건 2023-01-04 16:35 UTC 다.[^circleci]
**Okta(2023-11 root cause)** — 지원 시스템에 올라온 **HAR 파일에 담긴 세션 토큰**이 유출돼,
공격자가 그 토큰으로 **5개 고객(1Password·BeyondTrust·Cloudflare 등)의 정상 Okta 세션을
하이재킹**했다.[^okta][^helpnet] BeyondTrust 측 증언으로는 지원용 HAR 을 공유한 **30분 뒤 공격자가
그 브라우저 세션을 리플레이**했다.[^krebs]

핵심은 두 가지다. 첫째, **개별 요청만 보면 전부 정상**이다 — 유효 서명·미만료·2FA 통과.
둘째, 그래서 탐지는 **행위·문맥 신호(임파서블 트래블, 세션 중 소스 IP/ASN·UA 변경, 같은 토큰의
지리적 동시 사용)** 에 의존하고, 이는 실제로 어렵다. Okta 는 **14일간 로그에서 의심 다운로드를
식별하지 못했고**(공격자가 파일 탭으로 직접 이동해 다른 로그 이벤트 ID 를 남긴 탓), 외부
고객(BeyondTrust)이 준 의심 IP 로 비로소 상관이 풀렸다.[^okta][^krebs]

Watchman 이 이 클래스에 기여하는 지점은 그 **"탈취된 유효 세션이 쓰이기 시작한 순간"의
트리아지**다. 예방(세션이 애초에 안 털리게)은 Watchman 밖이지만, **탐지된 세션 이상을
트리아지해, 스테이트리스 JWT 의 구조적 한계까지 반영한 봉쇄를 사람에게 제안**하는 것은 이
에이전트의 자리다.

## 2. 정직한 경계 — Watchman 이 하는 것과 못 하는 것

이 클래스도 두 층으로 갈리고, 섞으면 과장이 된다.

**[예방層 — Watchman 밖, 상류(앱·인증) 통제]**
세션·토큰이 탈취되는 것 자체는 Watchman 이 못 막는다. 진짜 root fix 는 다음이다:
- **토큰 바인딩(sender-constrained tokens)** — DPoP·mTLS 로 토큰을 특정 키/클라이언트에 묶어,
  훔친 토큰만으로는 재사용 못 하게 함.
- **네트워크/위치 바인딩** — 세션을 소스 네트워크에 묶고 **IP/네트워크 변경 시 재인증 강제.**
  이것이 Okta 가 실제로 낸 fix(관리자 세션 토큰의 네트워크 위치 기반 바인딩)다.[^okta]
- **단명 TTL + 리프레시 토큰 회전** — 액세스 토큰 수명을 짧게, 리프레시는 1회용 회전.
- **쿠키 방어** — `httpOnly`·`Secure`·`SameSite` 쿠키, XSS 차단(토큰 탈취 경로 제거).
- **단말·자격 위생** — EDR, 업무 브라우저에 개인 프로필 로그인 차단(Okta 조치), HAR 공유 전
  세션 토큰 sanitize.

이게 진짜 대책이며, Watchman 이 이걸 한다고 표기하면 거짓이다.

**[탐지의 근본적 어려움 — 정직히]**
탈취된 토큰은 **모든 정적 검증(서명·만료·2FA)을 통과**한다. 그래서 탐지는 오로지 **행위·문맥
신호** — 세션 중 소스 IP/ASN·지오·UA 변경, 임파서블 트래블(두 위치 간 이동이 물리적으로 불가능),
같은 세션/`jti` 의 지리적 동시 사용 — 에 의존하고, 그 신호는 **인증·세션 감사 로그**가 수집돼야
나온다. Okta 의 14일 미탐이 보여주듯 **이 탐지는 로그 스키마와 룰이 제대로 서 있어야만 가능**
하다. **Watchman 은 그 detector 가 만든 세션 이상 alert 위에서 트리아지하는 계층이지, 요청 단에서
세션 하이재킹을 직접 잡는 물건이 아니다.**

**[탐지·대응層 — Watchman 의 자리, 특히 스테이트리스 JWT 의 한계 반영]**
세션 이상 alert 이 Alertmanager 로 오면 Watchman 이 read-only 로 트리아지하고 봉쇄를 **제안**한다.
여기서 이 클래스 고유의 핵심은 **스테이트리스 JWT 는 개별 토큰을 콕 집어 폐기할 수 없다**는 점
이다. 서버가 세션 상태를 안 들고 서명만 검증하므로, 훔친 토큰 하나만 죽이는 방법이 없다. 지렛대는
둘뿐이다 — **① 서명키(JWK) 회전** = 발급된 **모든** 토큰 무효화 = 전 사용자 대량 재인증(강력하지만
비용이 큼), **② `jti`/세션 denylist + 단명 TTL·리프레시 회전** = 상태 저장소를 두어 특정 토큰만
차단(운영 부담). 이 트레이드오프를 사람에게 정직히 제시하는 것이 Watchman 의 몫이다.

## 3. 탐지 신호 (인증·세션 감사 평면 → Alertmanager → Watchman)

세션 하이재킹은 **인증·세션 감사 로그**(로그인/토큰 발급·검증, 리버스프록시·API 게이트웨이의
세션 상관 로그)에 흔적을 남긴다.

| 킬체인 단계 | 관측 신호 | 소스(수집 전제) | Watchman 도달 |
|---|---|---|---|
| 세션 탈취(상류) | 단말 악성코드·HAR 유출·XSS — **Watchman 밖** | EDR·앱 보안 | (도달 안 함) |
| **재사용 개시** | **유효 세션/`jti` 가 새 소스 IP/ASN·새 UA 에서 재사용, 임파서블 트래블** | **인증·세션 감사 로그 + 행위 룰** | ES 수집 시 |
| **토큰 리플레이** | **같은 `jti`/세션이 두 위치에서 동시 활성(이전 IP 세션이 살아 있는 채로)** | **세션 상관 로그** | ES 수집 시 |
| 권한 상승·민감 액션 | 재사용 직후 관리 API·계정정보 대량 조회·export | API 게이트웨이·감사 로그 | ES 수집 시 |
| 데이터 유출 | 이그레스 급증, 대량 export | NetworkPolicy·Falco | ES 수집 시 |

픽스처 `fx-scn-05-jwt-session-replay-hijack.json` 은 이 중 **핵심 두 신호**(임파서블 트래블 재사용 +
토큰 리플레이)를 재현한다: 유효 세션 신원(`session:jwt:sub-user-3391:jti-b7c2a9e1`)이 발급 직후
국내 모바일 대역에서 정상 사용되다가 몇 분 안에 미등록 해외 ASN 에서 같은 토큰으로 재사용되고,
이전 IP 세션이 활성인 채 새 IP·새 UA 로 동일 `jti` 가 관측되며(각 요청 200), 새 위치에서 곧바로
`/api/v1/account/export` 등 민감 액션이 이어진다(라벨 `source=auth-session-audit`,
`severity=critical`).

**경로: 인증·세션 감사 로그 → (임파서블 트래블·동시세션 룰) → Alertmanager → Watchman webhook.**
Watchman 입장에서는 또 하나의 Alertmanager 알림이라 **새 수집 도구가 필요 없다.** 단, **이 알림이
존재하려면 세션 감사 로그 + 임파서블 트래블/동시세션 이상 룰이 먼저 서 있어야 한다**(§2·§6).

## 4. Watchman 의 트리아지 (관측→판단→제안, 실행 없음)

1. **관측(read-only)** — 기존 두 도구만 쓴다.
   - `es_search`: 해당 세션 신원(`sub`/`jti`)의 발급·검증 타임라인, 소스 IP/ASN·지오·UA 의 변화,
     같은 `jti` 의 지리적 동시 사용 여부, 재사용 이후의 민감 액션(관리 API·export)을 상관.
   - `kube_read`(GET/LIST): 인증·세션 워크로드(인증 서버·게이트웨이)와 그 설정을 조회해
     "정상 로밍/모바일 IP 변동/사내 VPN 이 이런 패턴을 만들 수 있는가"를 교차확인.
2. **판단** — **"정상 IP 변동(모바일 핸드오버·VPN·로밍) 아닌가"** 라는 대체가설을 강제 검토
     (평소 위치 이력·이동 가능 시간·기업 VPN 대역과 대조), 임파서블 트래블·토큰 리플레이 여부와
     확신도를 분류.
3. **제안(실행 아님)** — 카드에 담는 **봉쇄 제안**은 사람이 승인·집행한다:
   - **스테이트리스 JWT 한계 명시** 후 두 지렛대를 **트레이드오프와 함께** 제시 — *제안*:
     **① 서명키(JWK) 회전** = 전체 토큰 무효화·전 사용자 재인증(강력/고비용),
     **② `jti`·세션 denylist + 단명 TTL·리프레시 회전** = 해당 토큰만 차단(상태 저장소 필요).
   - 해당 **`sub` 강제 재인증·세션 강제 종료**, 의심 소스 IP/ASN **차단·레이트리밋** — *제안*.
   - **포렌식 보존**(세션 감사 로그·재사용 창(window) 스냅샷) 후 재사용 이후 접근한 객체·영향 산정
     — *제안*.
   - 예방層 후속(**토큰 바인딩/DPoP·네트워크 위치 바인딩·단명 TTL·쿠키 하드닝**) 착수 — *제안*.

이 시나리오에서도 6축 통제는 그대로 유효하다: 제안 카드는 **텍스트일 뿐**이고(④ 실행 도구
없음), 알림 본문에 섞인 지시는 주입 감지층이 잡으며(①), 에이전트는 여전히 읽기 전용·비루트·
이그레스 허용목록 안에서만 돈다(②③⑥).

## 5. 실측 (P4 정직 원칙 — 측정한 것만)

`fixtures/scenarios/fx-scn-05-jwt-session-replay-hijack.json` 을 **결정론적 mock 파이프라인**으로
1회 통과시킨 결과(`LLM_MODE=mock`, 감사로그 격리):

- 루프: **완주(state=완료, partial=None)**, finish 스키마 **유효**, evidence **1건**.
- 주입 감지(봉투 전체 JSON 스캔): **0건**.

> mock 은 **분류 정확도가 아니다.** 제어 흐름·출력 계약·주입 오탐 없음만 재현 검증한다(다른
> 뱅크와 동일 기준). 실 NIM 분류 정확도는 in-cluster 실관측 run 채점이 근거다.

동결 회귀 수치(레드팀 12/12·케이스 10/10)는 이 시나리오 추가와 **무관하게 유지된다** —
`fixtures/scenarios/*` 는 어느 게이트(run_eval·run_redteam·test_watchman)도 glob 하지 않으므로
정상·레드팀 뱅크 집계에 섞이지 않는다.

## 6. 범위와 남은 일 (정직)

- **된 것**: 알림 픽스처 + 킬체인 신호 매핑 + 트리아지/제안 설계(특히 **스테이트리스 JWT 는
  개별 폐기 불가 → 서명키 회전 vs denylist 트레이드오프 제시**) + mock 파이프라인 완주 실측.
- **아직 안 된 것(STRETCH)**: 이 클래스의 알림이 실제로 존재하려면 **인증·세션 감사 로그를
  ES/SIEM 으로 수집하고, '유효 세션이 세션 중 소스 IP/ASN·UA 변경·임파서블 트래블·같은 `jti`
  지리적 동시 사용' 이상 룰을 세워 Alertmanager 로 라우팅**하는 파이프라인이 필요하다. 나아가
  봉쇄를 실제로 집행하려면 **JWK 회전 도구·세션 denylist 저장소** 같은 인증 인프라가 전제된다.
  프로토타입 제출 범위 밖이며 ROADMAP STRETCH 로 둔다.
- **예방層(토큰 바인딩/DPoP·네트워크 바인딩·단명 TTL·쿠키 하드닝·XSS/악성코드 방어)은
  Watchman 밖**이다. 이 문서는 그 경계를 명시한다. Watchman 의 정직한 몫은 **탐지 후 "스테이트리스
  JWT 한계까지 반영한" 봉쇄 제안**이며, 세션 하이재킹의 원천 차단 자체가 아니다.
